# Changelog

## 0.5.0 - Unreleased

Changes since the previous versioned release, `0.4.2`.

This release raises the package's minimum platform and tools version, now supports apps with multiple scenes correctly, and substantially reduces the work shimmer effects do on every motion update.

### Breaking Changes

- Raised the minimum supported platform from iOS 14 to iOS 15.
- Updated the package to Swift tools version 6.0 and removed the explicit `swiftLanguageVersions` setting.
- `shimmer(mode:color:background:)` and `shimmer(isOn:color:background:)` now keep showing their background colour whenever the shimmer itself can't appear, matching `ShimmerView`. That covers motion updates not running and a `mode` that's off for the current colour scheme. Previously the background stayed painted when `MotionManager` was disabled but disappeared when the update interval was zero or the mode was off.
- `parallax(multiplier:maxOffset:)` is now `parallax(distance:maxOffset:)` and `distance` has no default value. The modifier should now produce a more accurate and visually pleasing parallax effect. Instead of offsetting a fixed amount per degree of rotation it treats the view as if it is anchord to a point `distance` points in front of the screen and offsetting according to where that point moved due to the rotation. This results in the effect easing at the extremes. This change also means the view can only move within a fixed circle instead of a square area defined by the max x and y offsets previously. The direction was also inverted on both axes before, which made a positive distance look like the view was set into the glass instead of sticking out. Now a positive distance will push the view out of the glass and a negative distance will push the view in. As before the view itself is never rotated or scaled.
- Made `rotation3dEffect(quaternion:anchor:anchorZ:perspective:)` unavailable, having deprecated it in `0.4.1` for being spelled with a lowercase `d`. Use `rotation3DEffect(quaternion:anchor:anchorZ:perspective:)`, which is otherwise identical.
- `MotionManager` is now one object per scene, created and owned by that modifier, rather than a single shared instance. Add `.motionManager(updateInterval:disabled:)` once near the top of each scene's view hierarchy rather than once for the whole app.
- Renamed `MotionManager.updateInterval` to `MotionManager.preferredUpdateInterval`, because all scenes receive samples at the fastest preferred interval. The rate they actually arrive at can be found at `DeviceMotion.updateInterval`. The old name is marked unavailable with a message pointing at the replacement.
- Moved all properties to do with device motion and interface rotation from `MotionManager` to `DeviceMotion` in order to improve performance and have one source of truth. Add `@EnvironmentObject var deviceMotion: DeviceMotion` to your view to access the environment object added with `.motionManager()`.
- Moved `interfaceRotation` and `deltaRotation` from `MotionManager` to `DeviceMotion`.
- Moved and renamed `MotionManager.quaternion` to `DeviceMotion.currentDeviceRotation`.
- Replaced `MotionManager.initialDeviceRotation` with `DeviceMotion.settledDeviceRotation`. Intial device rotation is no longer saved. The settled rotation is an alternative that tracks a previous device rotation and eases towards the current rotation rather than staying where it was. This new rotation is used in the new `DeviceMotion.deltaRotation` and the `parallax(distance:maxOffset:)` view modifier.
- Replaced `MotionManager.deviceOrientation` with `DeviceMotion.interfaceOrientation`. It reports which way the interface is facing rather than where the device is physically pointing, which is what every use of it in this package actually needed.
- Made `MotionManager.animatedQuaternion` unavailable. It held the same value as `quaternion` and only differed in being assigned inside a SwiftUI animation. Now that smoothing is applied by the view rather than the manager, the two would be identical. Use `DeviceMotion.currentDeviceRotation` and smooth between motion updates, matching the animation to the update interval with `.animation(deviceMotion.animation, value: deviceMotion.currentDeviceRotation)`.
- Made `MotionManager.changeDeviceOrientation()` unavailable because the manager responds to supported device-orientation changes automatically.
- Made `MotionManager.setUpdateInterval(_:)` and `MotionManager.setDisabled(_:)` unavailable. Pass values to `.motionManager(updateInterval:disabled:)` instead.
- Made `MotionManager.startMotionUpdates(updateInterval:disabled:setDeviceOrientation:)`, `MotionManager.restart()` and `MotionManager.stopMotionUpdates()` unavailable. Configure motion updates with `.motionManager(updateInterval:disabled:)`. Updates are managed automatically when their configuration changes, the device orientation changes, or the app moves between the foreground and background.
- Removed the `Quat4f` and `Vec3f` placeholders left behind by the move off FirebladeMath. They were already marked unavailable, so nothing that compiled against `0.4.2` referred to them.

### Changes

- Fixed effects not appearing at all when the app was launched in landscape. The rotation that compensates for the interface orientation came from `UIDevice.current.orientation`, which is unknown at launch and face up or face down whenever the device is lying flat. None of those are interface orientations, so they were discarded and the compensation fell back to its portrait value, leaving everything rotated ninety degrees away from the screen. It now comes from the window scene's interface orientation, which is readable from launch and unaffected by the device lying flat.
- Fixed effects appearing in the wrong orientation in landscape or portrait upside down interface orientations.
- Fixed multi-window apps stopping device motion when any one scene disappeared. Each scene now has its own `MotionManager` sharing one internal Core Motion service; the fastest enabled foreground interval drives that service, and updates stop only after no enabled foreground scene needs them. Backgrounding, closing, or disabling one scene does not stop another foreground scene's updates, and a scene disabled locally keeps its effects off while another scene is using motion updates.
- Fixed the `parallax` effect being left at a large offset after an interface orientation change. An interface orientation change restarts the sensor, and sometimes old motion updates would still go through with stale data. Samples left over from a previous run are now dropped, and the rotation the effect measures from is cleared whenever a run starts rather than only when the interface orientation changes, so a restart for any other reason, such as a scene appearing with a faster update interval, can't leave one from the old frame behind either.
- Improved shimmer performance substantially. `MotionManager` published the device rotation alongside its configuration, so `ObservableObject` re-evaluated every observing view on every motion update even when that view read nothing that had changed, and assigning the rotation in two separate transactions doubled that again. The rotation now lives in a separate `DeviceMotion` object observed only by the views that need it, smoothing between updates is applied by the view that displays it instead of by a global `withAnimation` in the manager, and the four-direction clone rotation used by `isShowingInFourDirections` is calculated once per motion update rather than once per view. Measured on an iPhone SE running iOS 15.8.5 with five shimmer effects in the view hierarchy, view body evaluations dropped from 38 to 5 per motion update.
- Added `DeviceMotion.animation`, a linear animation for smoothing values that change with device motion. Its duration matches the interval the shared service actually runs at, which is not necessarily the interval a scene asked for: a scene receives updates at the fastest rate any scene requested.
- Added `DeviceMotion.deltaRotation` which is used to rotate a SwiftUI view to match an initial device orientation. The initial rotation is reset whenever the interface orientation changes. Screen reference frame. It's used internally to create the `parallax` effect.
- Added `DeviceMotion.settlingDuration` and `DeviceMotion.setSettlingDuration(_:)`, which control how long the settled rotation takes to give up a turn the device makes and then holds. It can be changed while motion updates are running and takes effect from the next sample. Zero or less stops the settling. Every scene reads one shared `DeviceMotion`, so this applies to all of them.
- Added `DeviceMotion.interfaceToWorldRotation(offset:isShowingInFourDirections:)` which is used to rotate a SwiftUI view so it appears locked to an orientation in the real world. It's used internally to create the `deviceRotationEffect`.
- Added `Vec3.limited(to:)`, which shortens a vector to a maximum length without changing its direction. It's used internally to limit the `parallax` offset.
- Motion updates no longer animate unrelated state changes elsewhere in the app. Smoothing was previously applied with a global `withAnimation`, which set an animation on every state change that happened in the same run loop turn.
- Fixed the `shimmer` view modifier and `ShimmerView` ignoring `disabled`. They checked only whether the update interval was above zero, so with `disabled` set the mask and blend were still composited every frame over an effect that could never appear. The blend mode versions of `shimmer` now draw nothing at all in that case.
- Fixed shimmer and `LookingGlass` content being sized wrong when the app was opened in landscape. The screen was measured once at launch in whichever orientation the interface had started in, and that measurement was then swapped for landscape as though it had been taken in portrait. It now starts correct in any orientation and follows the interface as the device turns.
- Moved the shared Xcode workspace into `Example/` so the repository root remains a plain SwiftPM package. Previously, the root `.xcworkspace` was picked up by `xcodebuild` ahead of the package, and its local package reference only resolved by coincidence of the checkout's folder name.
- The package no longer reads `UISupportedInterfaceOrientations` from the app's `Info.plist`. It was used to discard device orientations the interface would not follow, which the window scene's interface orientation makes unnecessary.
- Added package documentation hosted on the Swift Package Index.
- Documented that the `shimmer` view modifier draws copies of the view, so state inside the view that changes its size or shape may not be reflected in the shimmer and any `onAppear` or `task` on the view may run more than once.
